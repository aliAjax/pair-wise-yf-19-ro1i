# hxyfront-62007 植物标本馆 · 馆藏柜位批量鉴定复核台

在原有「压制标本入库」脚手架上实现的**同物种批量鉴定复核 + 按物种代码柜层迁移调度**前端应用。所有数据仅保存在浏览器 `localStorage`，重开页面仍可查询，不上传服务器。

## 业务流程

1. **录入待鉴定**：采集号、物种代码/名称、采集人、海拔、采集地点、生境，录入后进入待鉴定队列。
2. **按物种组批**：鉴定员从待鉴定标本里按物种代码组批（可整组或勾选部分）。
3. **复核规则校验**：组内两两比对，凡与任一成员**采集人不同**或**海拔差超过 300 米**的标本，组批台会预判并要求逐份写明复核依据；批次支持「通用依据」一键填入。
4. **复核通过**：
   - 缺说明的标本**不进入本次结论**，退回待鉴定并记录原因；
   - 其余统一写入**鉴定人 + 鉴定日期**及复核依据，批次结论留档；
   - 随后按物种代码自动迁入指定柜层。
5. **满位暂停**：目标柜层满位时暂停迁移，**鉴定结论仍保留，标本留在原柜（暂存柜）**；迁移调度页按层分组展示，可在空位出现后**逐份重新选择**。
6. **柜层管理**：每个物种代码唯一指定一个柜层（可在柜层总览调整）；「腾空」已上柜标本会释放位号（位号可复用），标本退回已复核待迁，结论保留。
7. **同步联动**：柜位轨迹时间线、待鉴定/满位暂留等计数、状态筛选、单份标本详情弹窗在各处实时同步。

## 状态模型

`待鉴定 pending` → `批内复核中 batching` → `已复核待迁 reviewed`（可迁 / 满位暂留 / 未指定柜层）→ `已上柜 migrated`；腾空后回到 reviewed。

## 技术栈

React 19 + Vite + TypeScript，无后端、无第三方 UI 库；状态经 `structuredClone` 不可变更新后整体写入 `localStorage`。

## 本地运行

```bash
npm install
npm run dev        # http://localhost:62007
npm run typecheck  # 类型检查
npm run check:logic # 核心业务规则断言（组批/复核排除/满位暂留/腾空重迁）
npm run build
```

开发端口：62007

## 演示数据说明

- 色木槭 ACER-PA（4 份）：采集人不同 + 海拔差 >300m，每份都需写依据；
- 元宝槭 ACER-DA、枸骨 ILEX-LA：同质批次，免说明；
- 水杉 POFR-FR（3 份待鉴定 + 1 份已占 B-1 层，层容量 2）：复核后仅 1 份能迁入，2 份满位暂留，可腾空后逐份重选；
- 湖北紫荆 SOHU-HU：高海拔份与其余成员采集人不同、海拔差 >300m。

页面右上角「重置演示数据」可随时恢复初始状态。
